Every mcopt setting is a JVM system property that can be set in two ways: in `config/mcopt.properties` (the key without the `-D` prefix) or as a `-Dmcopt.*` argument in the launcher's JVM arguments. For example, `mcopt.own=true` in the properties file is equivalent to passing `-Dmcopt.own=true` in JVM arguments. The special `profile` key (without the `mcopt.` prefix) is only valid in `config/mcopt.properties` or as `-Dmcopt.profile=` on the command line.

<Note>
**Precedence order:** JVM command-line flags (`-Dmcopt.*`) **>** `config/mcopt.properties` **>** the active profile. A flag set on the command line is never overwritten by the properties file or the profile. A key in `mcopt.properties` wins over the profile's value for that key.
</Note>

<Accordion title="Profile & Core">

These flags control which preset profile is active and the top-level Metal renderer switches. The `profile` key selects a bundled set of defaults; individual flags in `mcopt.properties` or on the command line always win over the profile.

| Flag | Values | Default | Description |
|---|---|---|---|
| `profile` | `indie`, `alpha`, `recommended`, `none` | `indie` | Active preset profile. Set as `profile=NAME` in `config/mcopt.properties`, or as `-Dmcopt.profile=NAME` on the command line. `none` disables all profile settings (vanilla renderer). |
| `mcopt.metal` | `true` / `false` | `true` | Enable the native Metal rendering backend. Set to `false` to fall back to vanilla's OpenGL path while keeping all other mcopt optimizations. |
| `mcopt.metal.paceAdapt` | `true` / `false` | `false` | Adaptive frame pacing. Enabled by the `indie` and `alpha` profiles. Measured to produce 117–119 distinct frames/s vs 72–93 on a laptop, with lower p50/p99 frame times. |
| `mcopt.edgeCap` | `true` / `false` or integer | `false` | Cap the frame rate at 2× the display refresh rate (or a fixed integer fps) while the integrated server is generating terrain within RD + 32 chunks of the player. Prevents the render-distance edge going empty in fast flight over new terrain. Singleplayer and LAN host only; no effect in multiplayer. |

</Accordion>

<Accordion title="Far Terrain (mcopt.lod.*)">

Far terrain is an experimental opt-in feature for Macs with 10 or more GPU cores. Enable it with `mcopt.lod=true` in `config/mcopt.properties`. All `mcopt.lod.*` mixins are rejected when `mcopt.lod` is not set, so these flags are inert unless far terrain is enabled. The `recommended` profile turns far terrain on.

| Flag | Values | Default | Description |
|---|---|---|---|
| `mcopt.lod` | `true` / `false` | `false` | Enable far terrain. Also enabled by setting `mcopt.lod.radius`. For Macs with 10 or more GPU cores. |
| `mcopt.lod.radius` | integer (chunks) | `512` | How far the far terrain reaches, in chunks, to the edge of the coarsest tiles drawn. |
| `mcopt.lod.render` | `mesh`, `walk` | `walk` | Far terrain render path. `mesh` uses rasterized per-tile meshes with a GPU cull and indirect draws. All profiles that touch far terrain set `mesh`. |
| `mcopt.lod.fade` | `instant`, default | — | LOD hand-off fade style. `instant` suppresses the fade-in for a seamless transition. |
| `mcopt.lod.handoff` | `drawn`, default | — | Real-terrain hand-off strategy. `drawn` hands off once the real chunk is drawn. |
| `mcopt.lod.prio` | `screen`, default | — | Column streaming priority. `screen` prioritises columns visible on screen. |
| `mcopt.lod.publish` | `gpu`, default | — | Column publish path. `gpu` uses a GPU-side upload path. |
| `mcopt.lod.nativeNoise` | `neon`, default | — | NEON noise generation (bit-exact with the game's noise; measured faster on Apple Silicon). |
| `mcopt.lod.yield` | `missing:0`, default | — | Generation yield policy while the client lacks chunks in the render distance. `missing:0` yields immediately so real chunks are never delayed. |
| `mcopt.lod.handoffPush` | float | `0.9995` | Depth push for real terrain during hand-off, so real terrain wins coplanar tops over far terrain. |
| `mcopt.lod.pk` | `true` / `false` | `false` | Position-keyed draw lists (opt-in). |
| `mcopt.lod.realOcc` | `true` / `false` | `false` | Real-terrain occluder for far terrain (opt-in). |
| `mcopt.lod.seam` | direction string | — | Transition probe direction (debug). |
| `mcopt.lod.taa` | `true` / `false` | `false` | Temporal anti-aliasing for far terrain. |
| `mcopt.lod.small` | `true` / `false` | `false` | Small-GPU far terrain mode (MacBook Neo / 5-core GPU). Uses a quarter-size clipmap window to reduce geometry cost. |
| `mcopt.lod.n` | integer | `2048` (`512` with `small`) | Cells across each clipmap level's window (power of two). Larger = finer detail at the cost of memory (8 N² bytes per level). |
| `mcopt.lod.threads` | integer | cores − 4 | Generation worker thread count. Default leaves 4 threads for the game and GPU driver. |
| `mcopt.lod.walk` | `segmented`, `rows`, `serial` | `serial` | Column walk strategy. `segmented` spawns a thread per level for more parallelism on wide GPUs. |
| `mcopt.lod.rowSegs` | integer | `48` | Segments per column row when `mcopt.lod.walk=rows`. |
| `mcopt.lod.crownLevels` | integer | `1` (`2` with `small`) | Finest N levels that render tree crowns floating over ground. |
| `mcopt.lod.treeLevels` | integer | `1` | Finest N levels (at most 2) that render full game-generated trees. Level 1 requires block-exact ground data (~5× the generation work). |
| `mcopt.lod.crownShade` | float | `0.7` | Sky light factor under tree crowns. |
| `mcopt.lod.nearDetail` | `true` / `false` | `true` | Per-pixel detail on level 0 (smooth-lighting occlusion from neighbour columns, grass side band, material under top block on walls). |
| `mcopt.lod.textures` | `true` / `false` | `true` | Draw level 0 with the blocks' own textures (mipmapped). `false` = flat colours per face. |
| `mcopt.lod.plants` | `true` / `false` | `true` | Render grass, ferns and flowers on level 0. Requires `mcopt.lod.textures=true`. |
| `mcopt.lod.trees` | `true` / `false` | `true` | Render tree canopy on generated (never-visited) terrain. |
| `mcopt.lod.fineDensity` | `true` / `false` | `true` | Levels 0–1 use the game's final density function so cave mouths and pits break the surface as in real chunks. |
| `mcopt.lod.fineLevels` | integer | `2` | How many of the finest levels use final density (with `fineDensity`). |
| `mcopt.lod.fogStart` | float | — | Render-distance fade start as a fraction of the reach. Default uses the game's own (last tenth of reach). |
| `mcopt.lod.haze` | float | `1.0` | Stretch the game's environmental fog range to this multiple of the reach when longer than 1024 blocks. |
| `mcopt.lod.cache` | `true` / `false` | `true` | Disk cache for generated far terrain tiles. `false` regenerates every tile each session. |
| `mcopt.lod.cacheDir` | path | — | Override the per-world cache directory (default: `mcopt-lod` in the game directory). |
| `mcopt.lod.stats` | `true` / `false` | `false` | Log drawn and generated tile stats once per second. |
| `mcopt.lod.verify` | `true` / `false` | `false` | Compare each arriving real chunk against its far terrain column by column and log agreement (debug). |
| `mcopt.lod.draw` | `true` / `false` | `true` | Draw far terrain. `false` generates but draws nothing (useful for benchmarking generation alone). |
| `mcopt.lod.probe` | integer (ms) | `0` | Alternating A/B draw probe: toggles drawing on/off every N ms and logs the mean frame interval of each state. |
| `mcopt.lod.dump` | directory path | — | Raw dump of a frame's walk inputs for the offline harness. |
| `mcopt.lod.dumpFrame` | long | `600` | Frame number to dump when `mcopt.lod.dump` is set. |
| `mcopt.lod.chunks` | `true` / `false` | `true` | Summarize the game's own chunks (real chunks) in far terrain. |

</Accordion>

<Accordion title="Thread QoS (mcopt.qos.*)">

mcopt assigns Apple Quality of Service roles to Minecraft threads using `pthread_set_qos_class_self_np` from libSystem. On by default: the render thread is set to `user-interactive` and the integrated server thread to `user-initiated`. Measured improvements on the Neo: busy-area flight +17% fps, 1% lows +63%, MSPT −25%; hot laptop MSPT p99 −57%..−71%. Chunk builders are deliberately left at their default QoS (raising them cost 21% on the laptop's 0.1% lows).

| Flag | Values | Default | Description |
|---|---|---|---|
| `mcopt.qos` | `on` / `off` | `on` | Enable QoS role assignments globally. `off` disables all QoS mixins. |
| `mcopt.qos.render` | `background`, `utility`, `default`, `initiated`, `interactive` | `interactive` | QoS class for the render thread. |
| `mcopt.qos.server` | `background`, `utility`, `default`, `initiated`, `interactive` | `initiated` | QoS class for the integrated server thread. |
| `mcopt.qos.mesh` | `background`, `utility`, `default`, `initiated`, `interactive` | — | QoS class for chunk builder threads. Not set by default (deliberately left at system default). |
| `mcopt.qos.cull` | `background`, `utility`, `default`, `initiated`, `interactive` | — | QoS class for the cull thread. |
| `mcopt.qos.worker` | `background`, `utility`, `default`, `initiated`, `interactive` | — | QoS class for Worker-Main threads. |
| `mcopt.qos.io` | `background`, `utility`, `default`, `initiated`, `interactive` | — | QoS class for IO-Worker threads. |
| `mcopt.qos.log` | `true` / `false` | `false` | Log each QoS assignment (role name, thread name, and return code) as it happens. |

Set a role to `none` (e.g. `-Dmcopt.qos.render=none`) to remove that role from QoS management without disabling the others.

</Accordion>

<Accordion title="Startup (mcopt.startup.*)">

Startup flags defer or parallelize work that Minecraft performs during initialisation. All are behaviour-identical — the same objects and values are produced, just later or concurrently.

| Flag | Values | Default | Description |
|---|---|---|---|
| `mcopt.startup.narrator` | `lazy` | — | Create the macOS speech channel on the narrator's first use instead of in Minecraft's constructor (saves ~0.47 s on the MacBook Neo). Enabled by `lazy`. |
| `mcopt.startup.crashPreload` | `async` | — | Build the warm-up crash report (which runs an external hardware-probe command, ~0.43 s on the Neo) on a daemon thread. The memory reserve is still allocated first on the main thread. |
| `mcopt.startup.blockCache` | `parallel`, `digest`, `parallel-digest` | — | Block state cache init strategy. `parallel` computes every block state's cache (shapes, light, sturdy faces) in parallel after the registry loop. `digest` computes serially and prints a digest. `parallel-digest` runs parallel and prints a digest for comparison. |
| `mcopt.startup.fadeMs` | integer | `1000` | Loading overlay fade-out duration in milliseconds (fade-in is N/2 ms instead of 500). A visible UI change, not a game-logic change. |
| `mcopt.startup.blockCacheDump` | file path | — | Write a per-state block cache digest to the given file (used with `blockCache=digest` or `parallel-digest`). |

</Accordion>
